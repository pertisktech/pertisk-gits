Pertisk CI runner deployed.

  Release:    {{ .Release.Name }}
  Namespace:  {{ .Release.Namespace }}
  Replicas:   {{ if .Values.autoscaling.enabled }}{{ .Values.autoscaling.minReplicas }}-{{ .Values.autoscaling.maxReplicas }} (HPA){{ else }}{{ .Values.replicaCount }}{{ end }}
  API URL:    {{ .Values.apiUrl }}

All pods share one runner token (runner pool). Each pod claims at most one job;
scale replicaCount (or HPA) for more concurrent pipelines.

  kubectl get pods -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }}
  kubectl logs -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }} -f --prefix

Register once in the UI, then:

  helm upgrade {{ .Release.Name }} ./deploy/helm/pertisk-runner \
    --reuse-values --set replicaCount=3

Note: GitLab Kubernetes executor spawns a new pod per job. Pertisk uses long-lived
runner pods with shell execution — see docs/RUNNERS.md#kubernetes-multi-replica.
